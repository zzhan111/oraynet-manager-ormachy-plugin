# PgyBox Omarchy Plugin 设计计划

## 目标

用一个只读、低干扰的顶栏插件回答四个问题：

1. 当前网络是否正常？
2. 实时上下行是多少？
3. 哪些设备正在占用网络？
4. 流量、DHCP 与组件是否需要关注？

## 交互与布局

### 顶栏

保持现状，不继续堆信息：

- Oray 图标：有可用快照时白色，无连接时灰色。
- 文本：仅显示实时 `↑/↓` 速率。
- 点击速率：折叠；点击折叠后的图标：恢复速率。
- 点击图标：打开详情面板。
- 中键：刷新；右键：打开并保护 PgyBox 页面。

### 面板

按优先级从上到下：

1. **实时状态**
   - 上下行速率。
   - 正常、数据过期、页面未打开、未登录等明确状态。
   - 最近更新时间。

2. **设备摘要**
   - 在线设备数、活跃设备数。
   - Top 3 实时流量设备：名称、上行、下行。
   - 不展示完整 MAC；未知设备显示掩码名称。

3. **流量用量**
   - 7 天 / 30 天累计流量。
   - 月度已用 / 限额进度条。
   - 接近限额时使用警告色。

4. **网络健康**
   - DHCP 是否启用、活跃租约数、地址池利用率。
   - 待更新组件数；列出异常组件名。
   - 固件更新只提示，不提供升级按钮。

5. **按需诊断（后续）**
   - 用户输入目标后主动运行 ping/traceroute。
   - 默认不运行，不做后台探测。

## 首版范围

先只增加 **设备摘要**：

- 在线设备总数。
- 活跃设备数。
- Top 3 实时流量设备。

原因：Jev 评分最高（3.64/4），页面已有稳定设备表，且无需引入历史存储或写操作。

明确暂不做：

- 历史趋势和数据库。
- WiFi、WAN、LAN、QoS、Hosts、VPN、ARP、Firewall 配置。
- 重启、升级、限速、拉黑设备等写操作。
- APP Center、日志与网络检测。

## 数据架构

继续复用浏览器登录态，但不提取或保存 Cookie、Token 和认证头。

```text
已登录 PgyBox tab
  → CDP Network 观察目标 API 响应
  → Python watcher 校验并归一化 JSON
  → QML 保留每个区块最后一次成功快照
  → 顶栏与面板渲染
```

统一快照建议：

```json
{
  "ts": 0,
  "status": "ok",
  "rates": { "up": 0, "down": 0 },
  "devices": {
    "online": 0,
    "active": 0,
    "top": [
      { "name": "device", "up": 0, "down": 0 }
    ]
  },
  "traffic": null,
  "dhcp": null,
  "updates": null
}
```

每个区块独立判断新鲜度；某一接口失败时，不覆盖其他区块的最后成功数据。

## 状态规则

- `ok`：目标区块在新鲜窗口内更新。
- `stale`：有旧数据，但超过新鲜窗口。
- `no-page`：没有 PgyBox tab。
- `unauthorized`：页面存在但登录失效。
- `error`：响应格式或 CDP 异常。

错误文案面向用户，不直接显示内部异常栈。

## 实施阶段

1. **设备摘要**：识别设备列表 API，扩展 watcher 契约，面板加入 Top 3。
2. **流量用量**：接入 7/30 天与月度限额，只读告警。
3. **DHCP 健康**：活跃租约数和地址池利用率。
4. **版本健康**：组件待更新数与固件更新提示。
5. **按需诊断**：仅在用户明确触发时增加 ping/traceroute。

每阶段完成后再决定是否进入下一阶段，避免一次性扩展多个不稳定接口。

## 验收标准

- 顶栏保持当前尺寸和交互，不因新增面板内容变宽。
- PgyBox 页面打开且登录时，设备摘要能在 10 秒内更新。
- 单个数据源失败不清空其他有效数据。
- 页面关闭或登录失效时，状态可解释且不误报在线。
- 插件不保存凭据、不输出认证信息、不修改路由器状态。
